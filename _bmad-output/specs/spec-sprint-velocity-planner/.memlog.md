- (capability) CAP-1 Team Roster & Allocation -- intent: PM maintains a roster and splits each member's time across a shared, PM-configurable set of allocation categories as percentages. success: add/remove(soft-delete)/re-allocate reflected in current/future Capacity without altering closed-Sprint history. Source: PRD FR-1..FR-5.
- (capability) CAP-2 Leave & Holidays -- intent: PM records Planned Leave, Emergency Leave, and company-wide Holidays that reduce Capacity (one member's, or everyone's for Holidays). success: distinct-working-days-lost formula holds for overlapping Holiday-in-Leave and weekend-spanning ranges (PRD FR-9 worked example); emergency entries recalculate immediately. Source: PRD FR-6..FR-10.
- (capability) CAP-3 Capacity & Velocity Calculation -- intent: system computes per-person and team Capacity in hours per Sprint, tracks Planned vs PM-confirmed Actual Velocity (sourced from YouTrack logged time) across Sprints as a trend. success: closed-Sprint snapshot (Capacity, Allocation breakdown, confirmed Actual Velocity) stays unchanged regardless of later roster changes; active-Sprint numbers stay live. Source: PRD FR-11..FR-15; Architecture AD-1, AD-2.
- (capability) CAP-4 YouTrack Integration (via MCP) -- intent: PM connects to one YouTrack project via MCP, browses/pulls Backlog Issues into a Sprint read-only, and pulls logged hours at Sprint close. success: viewing an already-planned Sprint never depends on YouTrack being reachable; a bad connection surfaces a clear inline error at config time. Source: PRD FR-16..FR-18; Architecture AD-3.
- (capability) CAP-5 Sprint Planning -- intent: PM creates, plans (assign issues to members with an advisory over-allocation warning), and closes a two-week (configurable) Sprint; exactly one Sprint open at a time. success: one-screen Sprint Plan view (roster, Capacity/Allocation breakdown, Leave/Holidays, assigned issues, planned-vs-available); a second Sprint cannot be created while one is open. Source: PRD FR-19..FR-23; Architecture AD-6.
- (capability) CAP-6 Read-Only Team View -- intent: any team member views the current Sprint's plan via an unguessable shared link, no login, no edit capability. success: the share route never executes a write action even if attempted; viewable independent of the PM's own session. Source: PRD FR-24; Architecture AD-4, AD-5.
- (constraint) No auth/login for anyone in v1 (PM or team); access gated only by network trust (PM surface) and an unguessable link token (Team View).
- (constraint) Single YouTrack Project connection in v1, not multi-project.
- (constraint) Exactly one Sprint may be open at a time.
- (constraint) v0 hosting: app runs on the PM's own machine; CAP-6 (Team View) is not reachable independent of that machine being on/networked until hosting is revisited.
- (constraint) Actual Velocity (CAP-3) sources YouTrack logged time-tracking hours -- a practice the team does not yet have; this is a new operational dependency, not a detail the system can route around.
- (decision) Non-goals: not a YouTrack replacement (read-only only); not multi-team/multi-PM; not a system of record for HR/payroll leave; no team-member accounts/login/self-service; no mobile app, notifications, reporting/export, or automatic issue carry-over between Sprints.
- (decision) Success signal: the PM plans and closes real two-week Sprints in this tool instead of a spreadsheet, sprint over sprint, trusting the Capacity number enough to commit without re-checking the math by hand; Velocity History accumulates real Planned-vs-Actual data over time.
- (assumption) Carried from PRD Assumptions Index: YouTrack integration read-only in v1; estimate hours from one configurable custom field with manual fallback; no-auth PM session assumes trusted deployment (v0 concretely means a single laptop, not yet a broader 'trusted network').
- (question) Is the team's willingness/ability to log time in YouTrack (required for CAP-3's Actual Velocity) confirmed, or does it need validating before build?
- (question) What threshold defines 'close enough' between Planned and Actual Velocity? Deliberately deferred until baseline data exists (PRD SM-2).
- (question) When should always-on hosting be revisited so CAP-6 is reachable by the team, not just the PM?

- (event) Run started. Sources confirmed: PRD prd-pm-2026-08-12, Architecture Spine architecture-pm-2026-08-12, SPEC.md spec-sprint-velocity-planner, epics.md (4 epics/22 stories). Form factor: web, Next.js. Two personas: PM (sole editor, desktop-primary) and Team Member (read-only viewer via shared link).
- (decision) Aesthetic mandate: user wants impressive/stylish/modern, latest web trends -- not a generic templated admin-dashboard look, despite being a data-dense B2B internal tool. Brand: white canvas + purple accent #7c5cff.
- (decision) Design thesis: 'capacity made visible' -- the product's core value is turning invisible, messy reality (leave, holidays, allocation splits) into a trustworthy visible number. Visual language should read as a precision instrument/ledger, not a generic SaaS dashboard.
- (decision) Color system (6 named tokens): surface-base #FFFFFF, surface-raised #F7F6FB (violet-tinted off-white), ink-primary #16121F (near-black, violet undertone), ink-muted #6B6478, accent-primary #7C5CFF (primary actions, active states, 'available capacity' signal), signal-leave #E8794A (warm amber -- reserved specifically for hours lost to Leave/Holiday, functional not decorative). Purple used sparingly/precisely, never as a decorative gradient wash -- differentiates from generic purple-SaaS/Linear-clone look.
- (decision) Typography signature: numeric data (hours, %, velocity figures) rendered in a monospace face with tabular figures (e.g. JetBrains Mono / IBM Plex Mono) -- functionally justified (columns of numbers align cleanly) and doubles as the visual signature ('precision instrument' feel). Body/UI text stays a plain, invisible workhorse sans (Inter or system-ui) -- personality is spent on the numeric treatment, not everywhere.
- (decision) Signature element: 'Capacity Ledger' -- a full-width segmented horizontal bar (purple = available Capacity, amber = hours lost to Leave/Holiday) shown prominently at the top of the Sprint Plan Overview, functioning as the dashboard's 'hero' since it literally visualizes the product's core value prop. Per-person breakdown as a scannable table below it.
- (decision) Depth/shape: thin hairline borders + minimal shadow for cards (avoid glassmorphism/heavy-shadow cliches); moderate corner radius (~8-12px, shadcn rounded-lg territory) for cards/inputs, pill radius reserved for status chips (Planned Leave/Emergency/Holiday/over-allocation tags) so tags read as distinct signal elements. Motion: minimal and purposeful -- e.g. the Capacity Ledger bar animates when Capacity recalculates (emergency leave entered), reduced-motion respected; no decorative page-transition fluff.
